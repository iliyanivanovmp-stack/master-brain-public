CAPTURE ★

REFLECT

QUERY
Answers "what's my strategy on X?" in text

/strategy command → opens interactive HTML dashboard to edit visually

Skill 3 of 3

/wrap-up

Session Logger

Run at the end of every meaningful session. Generates a structured summary and embeds it into Pinecone's personal-memory namespace — making it instantly searchable via /recall forever.

WHAT GETS SAVED
What was worked on this session
Decisions made and why
Key outputs and artifacts created
What's next / open threads
Timestamp + date metadata for recall
THE COMPOUNDING EFFECT

One session = modest value. Ten sessions = searchable archive. Fifty sessions = an AI that knows your entire work history. The system compounds: each wrap-up makes every future /recall richer.

HABIT RULE

Before closing Claude Code → run /wrap-up. Takes 30 seconds. Compounds forever.

Why It's Built This Way

Four design decisions that matter

1
Agents never browse folders — they query
Browsing is O(n). Querying Pinecone is O(1). With 37+ knowledge files and growing, semantic search is the only approach that scales. The index is the interface.
2
One index, three namespaces — not three indexes
Knowledge, memory, and execution registry live in the same Pinecone index under separate namespaces. Single connection, predictable schema, one ingest pattern per bucket.
3
Strategy is a file, not a query
Strategic state must be available before any query can run. A pointer in CLAUDE.md loads it automatically. No skill invocation needed. It's the foundation, not a feature.
4
No framework, no abstraction — just three primitives
One markdown file. One vector index. Three skills. There's no agent state machine, no opinionated memory framework. Everything is auditable, version-controllable, and replaceable.
