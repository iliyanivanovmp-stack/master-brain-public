# Bulk Ingest — Loading Knowledge into Pinecone

This is for **Bucket 02 (Knowledge)** — books, transcripts, expert references, community sentiment dumps. Stuff you want semantic-searchable but isn't generated by your Claude conversations.

You only need this if you're loading bulk content. The `wrap-up` skill handles ongoing session-by-session capture automatically.

---

## What to ingest

Common knowledge sources:

| Source | Why |
|---|---|
| Your own video transcripts | Stop forgetting what you've already taught |
| Books / book notes | Expert frameworks at your fingertips |
| Podcast transcripts | Long-form expert thinking |
| Community / customer messages | Real customer language for marketing & decisions |
| Newsletter archive | Track what you've published |

---

## The pattern

For every knowledge source:

1. **Create a separate Pinecone index** (e.g. `hormozi`, `your-youtube`)
2. **Chunk the content** — typically 300–500 word chunks with 50-word overlap
3. **Embed each chunk** using `llama-text-embed-v2` (Pinecone integrated inference)
4. **Upsert with metadata** — source title, date, chunk number, URL
5. **Add the index to `~/.claude/memory-config.json`** so `recall` knows about it

---

## Minimal Python ingest script

```python
# bulk_ingest.py
# Usage: python bulk_ingest.py --index hormozi --source ./hormozi-100m-offers.md

import os
import argparse
import hashlib
from pinecone import Pinecone

pc = Pinecone(api_key=os.environ["PINECONE_API_KEY"])

def chunk_text(text, size=400, overlap=50):
    words = text.split()
    chunks = []
    i = 0
    while i < len(words):
        chunk = " ".join(words[i:i+size])
        chunks.append(chunk)
        i += size - overlap
    return chunks

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--index", required=True)
    parser.add_argument("--source", required=True, help="Path to markdown file")
    parser.add_argument("--title", required=True, help="Title of source (e.g. '$100M Offers')")
    args = parser.parse_args()

    index = pc.Index(args.index)
    with open(args.source) as f:
        text = f.read()

    chunks = chunk_text(text)
    records = []
    for i, chunk in enumerate(chunks):
        # Pinecone integrated inference embeds inline
        records.append({
            "id": hashlib.md5(f"{args.title}-{i}".encode()).hexdigest(),
            "values": pc.inference.embed(
                model="llama-text-embed-v2",
                inputs=[chunk],
                parameters={"input_type": "passage"}
            )[0].values,
            "metadata": {
                "source": args.title,
                "chunk_index": i,
                "text": chunk
            }
        })

    # Batch upsert (100 at a time)
    for i in range(0, len(records), 100):
        index.upsert(records[i:i+100])
        print(f"Upserted {i+100}/{len(records)}")

    print(f"Done. {len(records)} chunks loaded into '{args.index}'.")

if __name__ == "__main__":
    main()
```

Run it:

```bash
export PINECONE_API_KEY=<your-key>
python bulk_ingest.py --index hormozi --source ./100m-offers.md --title "$100M Offers"
```

---

## Tips

- **One source = one index** when the source is large (full book, full podcast archive).
- **Multiple small sources = one index** when they're related (e.g. all your YouTube scripts in one `your-youtube` index).
- **Always include the chunk text in metadata** — Pinecone returns metadata with results, so you don't need to re-fetch the source.
- **Re-ingesting?** Use deterministic IDs (hash of title + chunk index) so re-runs upsert instead of duplicating.
- **Privacy note:** Pinecone is cloud-hosted. Don't ingest content you can't put on AWS.

---

## After ingest

Add the new index to `~/.claude/memory-config.json`:

```json
{
  "knowledge_indexes": [
    { "name": "hormozi", "topic": "Alex Hormozi business frameworks" }
  ]
}
```

Now `recall` will route Hormozi-flavored queries to that index automatically.
